# Native complete reference boundary

This is an implementation contract/audit fragment for the single Native Runtime engineering project, not a separate completion report. All execution evidence is host software/WSL/MuJoCo; hardware execution readiness remains false.

`companionbot::follow::TwoPathProducer` is the complete owner of the current Stage 5/6 sparse command scheduler, accepted baseline/candidate window, FULL lock, projected-exit observation gate, velocity reference lifecycle, quiet snap, independent feedforward fade, pending command and 25-sample ReferenceBlock output. Its constructor receives canonical `TwoPathConfig`, optional `FullPlanSolver`, and reference epoch. `produce(start_tick,generated_time,source_time,velocity,yaw,observe)` returns the existing 640-byte v1 ReferenceBlock plus float64 samples/diagnostics; `reset(position,velocity,new_epoch)` clears old producer state. MCU task/physical arm permission is not owned by this class.

The synchronous FULL solver callback crosses a low-frequency mathematical data boundary only when a new FULL plan has actually been accepted. `PlanRequest` contains the current reference four-state, acceleration, accepted velocity and distinct request/execution times. The existing `RuckigFullHorizonVelocityPlanner.plan` performs unchanged installed Ruckig 0.19.4 and compiled SciPy LSQR or cached-KKT mathematics. `FullPlan.from_rolling` copies complete state/acceleration/shaped-finish/feedforward arrays once per accepted plan, validates their geometry, then returns ownership to C++. No Python callback occurs for individual reference samples. The standard pybind11 functional adapter manages the callback GIL; no custom executor, solver or communication framework is introduced.

Whole-block `compute_wall` and thread CPU include the callback/GIL interval, array conversion, native lifecycle/scheduling and wire encoding. Simulated transport arrival uses whole-block compute time as before. The existing raw mathematical planner's timing diagnostics retain their original meaning and are not substituted for whole-block latency. Python's historical producer-internal measurement excluded row construction/encoding, so performance comparisons must use equivalent outer boundaries.

`NavigationRuntime` now holds this same producer for GUIDE_TO and FOLLOW. Nav2 policy remains immediate interruptible LIGHTWEIGHT changes with the existing envelope. FOLLOW uses the existing forced-FULL/defer-exit policy. A policy switch requires a stationary producer reset and an MCU stopped state, or the original local-estimate stopped bounds at zero-reference startup. Existing C99 MCU epoch/revocation and physical arm responsibilities remain separate. A mathematical solver, policy or encoding exception first establishes a local C99 HARD_STOP barrier with independent reason 513, revokes the task, and then propagates the exception. There is no Python runtime fallback.

All Python-facing methods that can wait for the runtime mutex release the GIL before acquiring it. A FULL solver can then reacquire the GIL without deadlocking a concurrent diagnostic report. The producer itself has one runtime caller; it does not implement an additional thread scheduler. The runtime consumes the same typed 20 Hz software MCU RobotState delivery before feeding `FollowController` state history. Its 500 Hz authority read is a mutex-consistent POD execution snapshot rather than a copied diagnostic dictionary/string set.

The candidate window is capped at 1024 entries; each lifecycle event family retains at most 16384 rows, with explicit overwrite totals. Plan input size is bounded and rejects invalid/nonfinite/start-discontinuous/terminal-invalid plans. These are operational memory bounds, not altered control durations. State/intent geometry remains logged by the perception/follow measurement owner; the native reference contract carries motion intent rather than inventing a synthetic measured person position.

## Conservative obstacle/braking engineering boundary

The guard uses the existing all-direction LiDAR minimum, canonical robot radius plus LiDAR-origin triangle bound and three simulation range-noise standard deviations. Its fixed reaction interval is the existing 0.2 s visual source deadline + 0.35 s scan source deadline + one 0.002 s MCU tick. These sources are hashed by `native_follow.clearance_configuration`; they are not fitted to outcomes.

The guard runs the original `cb_brake_init/step` law for current reference and sensorized velocity, and for positive/negative analytic reaction-end speed and acceleration corners. It accumulates absolute velocity trapezoids, including reversals. Once the original brake is settled, hidden-state handoff has completed, and its unsaturated `-2*v` target is reachable in one jerk step, future reference velocity follows `(1-2*dt)*v`; the remaining absolute displacement is at most `abs(v)/2`. This retained tail is added rather than discarded. The separately derived maximum projection-step allowance fails closed on exhaustion.

Reaction displacement is bounded by `min(vmax*T, speed*T + 0.5*amax*T*T)`; reaction-end speed is bounded by `min(vmax, speed+amax*T)`. The subsequent C99 brake is also evaluated at that end-speed bound, so possible continuing acceleration cannot disappear from stopping-distance accounting. The four brake-corner evaluations are an engineering envelope and directed software validation, not a formal reachable-set proof for every physical robot state. Ruckig's time-optimal terminal-velocity trajectory is deliberately not described as such a proof. Physical tracking, actual actuator response and sensor uncertainty remain separate validation limits; no Pi/STM32 certification is implied.

Observed speed/consumed reference acceleration outside the declared canonical profile envelope invalidate guard readiness; the only included numerical allowance is the existing ReferenceBlock float32 rounding of those limits. The conservative reaction envelope can reject FOLLOW near the original desired distance or shelves. Such a rejection must remain visible and cannot be addressed by relaxing source deadlines, shrinking the robot radius, changing the frozen governor, or silently substituting actor ground truth.
